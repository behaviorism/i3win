# i3win Plan 3 — Bar and Status Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An i3bar-style bar on each monitor: clickable workspace buttons, a binding-mode indicator, and a status area driven by `status_command` (i3bar JSON protocol with click events, or plain text). Also ship `i3win-status.exe`, which prints CPU, memory, disk, battery and time in that protocol.

**Architecture:** The protocol parser and the workspace-button model are pure code in `i3win-core`. The bar's layout is a pure function in the platform crate with injected text measurement. Bar windows are GDI-painted topmost popups owned by `App`. The status process runs as a child with piped stdin/stdout; a reader thread posts parsed blocks to the main thread via `MainMsg`. The core already subtracts the bar height from each output (`arrange::bar_height`), so tiled windows never sit under the bar.

**Tech Stack:** Rust 2021, `serde = { version = "1", features = ["derive"] }`, `serde_json = "1"`, `chrono = "0.4"`, `windows = "0.58"`.

**Spec:** `docs/superpowers/specs/2026-10-16-i3win-design.md`
**Depends on:** Plans 1 and 2 completed. Read `crates/i3win/src/app.rs`, `mainloop.rs`, `win/gdi.rs` and `core/src/arrange.rs` before starting.

## Global Constraints

- Everything from Plans 1–2's Global Constraints applies.
- `i3win-core` may now depend on `serde` (derive) and `serde_json`. Nothing else.
- The bar never takes focus: `WS_EX_NOACTIVATE`, and `WM_MOUSEACTIVATE` → `MA_NOACTIVATE`.
- The status reader thread never touches `App`. It only calls `mainloop::post`.
- `status_command` is spawned as `cmd.exe /C <command>` (`raw_arg`), with `CREATE_NO_WINDOW`, stdin and stdout piped, stderr null, and the child's `PATH` prefixed with the directory of `std::env::current_exe()` (so `i3win-status` next to `i3win.exe` is found).
- Bar geometry, all scaled by the output's `scale` and rounded: button horizontal padding 5 px, gap between buttons 1 px, left margin 0, right margin 4 px, separator line 1 px.

## Review Focus

1. **A status command that prints garbage, or a half-written JSON line**: the bar keeps the previous blocks and keeps reading. → test `bad_lines_keep_going` in Task 1.
2. **A status command that exits or can't be found**: the bar shows one block `status_command exited` in urgent colors and doesn't respawn in a loop. → test `exit_block_text` in Task 6.
3. **More status text than fits next to the workspace buttons**: blocks that would overlap the buttons/mode indicator are dropped from the left (oldest first), never drawn over the buttons. → test `status_never_overlaps_buttons` in Task 3.
4. **Workspace names with quotes or spaces** (`"my ws"`) clicked in the bar must switch to exactly that workspace. → test `click_command_quotes_name` in Task 3.
5. **Fullscreen windows**: the bar on that monitor hides and comes back when fullscreen ends. → manual check in Task 4.

**Interfaces:**
- Produces:

```rust
#[derive(Clone, Debug, PartialEq, Default, serde::Serialize, serde::Deserialize)]
pub struct Block {
    pub full_text: String,
    #[serde(default, skip_serializing_if = "Option::is_none")] pub short_text: Option<String>,
    #[serde(default, skip_serializing_if = "Option::is_none")] pub color: Option<String>,       // "#rrggbb"
    #[serde(default, skip_serializing_if = "Option::is_none")] pub background: Option<String>,
    #[serde(default, skip_serializing_if = "Option::is_none")] pub border: Option<String>,
    #[serde(default, skip_serializing_if = "Option::is_none")] pub name: Option<String>,
    #[serde(default, skip_serializing_if = "Option::is_none")] pub instance: Option<String>,
    #[serde(default)] pub urgent: bool,
    #[serde(default = "yes", skip_serializing_if = "is_true")] pub separator: bool,
    #[serde(default, skip_serializing_if = "Option::is_none")] pub separator_block_width: Option<i32>, // default 9 when drawing
}
pub struct StatusParser { mode: ParserMode, pub click_events: bool }   // enum ParserMode { Start, Plain, Json }
impl StatusParser { pub fn new() -> Self; pub fn feed_line(&mut self, line: &str) -> Option<Vec<Block>>; }
pub struct ClickWriter { started: bool }
impl ClickWriter { pub fn new() -> Self; pub fn encode(&mut self, name: Option<&str>, instance: Option<&str>, button: u8, x: i32, y: i32) -> String; }
```

Rules:
- `feed_line` in `Start` mode: a trimmed line starting with `{` that parses as a JSON object with an integer `version` key → `Json` mode, read `click_events` (default false), return None. Otherwise → `Plain` mode and handle the line as Plain.
- `Plain`: return `Some(vec![Block { full_text: line.trim_end().into(), ..Default::default() with separator: true }])`.
- `Json`: trim; a line equal to `[` → None. Strip one leading `,`, trim again; parse as `Vec<Block>`; Ok → Some; Err → None. Unknown JSON keys are ignored (serde default behavior; do not `deny_unknown_fields`).
- `ClickWriter::encode`: the first call returns `"[\n"` + object + `"\n"`; later calls return `","` + object + `"\n"`. Object: `{"name":…,"instance":…,"button":N,"x":X,"y":Y}`, where name/instance are JSON `null` if None. Build it with `serde_json::json!`.

### Task 3: Pure bar layout

**Files:**
- Create: `crates/i3win/src/bar_layout.rs`; Modify: `main.rs` (`mod bar_layout;`)

**Interfaces:**
- Consumes: `WorkspaceButton`, `Block`, `config::{BarColors, BarColorTriple, Color, parse_color}`.
- Produces:

```rust
#[derive(Clone, Debug, PartialEq)] pub enum ItemKind { Workspace(String), Mode, Block(usize) }
#[derive(Clone, Debug, PartialEq)] pub struct BarItem { pub kind: ItemKind, pub rect: Rect, pub text: String, pub fg: Color, pub bg: Option<Color>, pub border: Option<Color> }
#[derive(Clone, Debug, PartialEq)] pub struct BarLayout { pub items: Vec<BarItem>, pub separators: Vec<i32> } // separator x positions (bar-relative)
pub fn layout_bar(width: i32, height: i32, scale: f32, buttons: &[WorkspaceButton], show_buttons: bool, mode: Option<&str>, blocks: &[Block], colors: &BarColors, measure: &dyn Fn(&str) -> i32) -> BarLayout;
pub fn click_command(name: &str) -> String;   // workspace "<name with \ and " escaped>"
pub fn hit_test(layout: &BarLayout, x: i32, y: i32) -> Option<&BarItem>;
```

Rules (`s(v) = (v as f32 * scale).round() as i32`; all rects are bar-relative):
- Left side, x starts at 0. If `show_buttons`: for each button, `w = measure(name) + 2*s(5)`, rect `(x, 0, w, height)`; colors: urgent → `urgent_workspace`, else focused → `focused_workspace`, else visible → `active_workspace`, else `inactive_workspace` (fg=text, bg=background, border=border); `x += w + s(1)`.
- Mode: if `mode` is `Some(m)` and `m != "default"` → same sizing, `binding_mode` colors, kind `Mode`.
- `left_end` = x after the last left item.
- Right side: iterate blocks from LAST to first. For the last block, `right = width - s(4)`. For every earlier block i, `gap = s(blocks[i].separator_block_width.unwrap_or(9))` and `right = prev_placed.rect.x - gap`. `w = measure(full_text)`. If `right - w < left_end` → stop (drop this block and every block to its left). Otherwise place it: rect `(right - w, 0, w, height)`; fg = `parse_color(block.color)` or `colors.statusline`; bg/border = parsed block values; urgent blocks use `urgent_workspace` colors. Only when block i (not the last) is placed and `blocks[i].separator` is true → push separator x = `prev_placed.rect.x - (gap + 1) / 2`.
- Items order: left items in order, then block items in left-to-right order (reverse the collected list).

  - `pub fn cpu_percent(prev: (u64, u64, u64), now: (u64, u64, u64)) -> f64` — tuples are (idle, kernel, user) FILETIME ticks; kernel includes idle; `busy = (dk + du - di)`, `total = dk + du`; returns `100 * busy / total`, or 0.0 if total == 0.

  - `pub fn disk_block(drive: &str, free_bytes: u64) -> Block` — `"{drive} {:.1} GiB"`, free/1024³, name `disk`.
  - `pub fn battery_block(percent: u8, ac_online: bool) -> Block` — `"{CHR|BAT} {p}%"`, name `battery`, `urgent = !ac_online && percent < 15`.
  - `pub fn time_block(now: chrono::DateTime<chrono::Local>) -> Block` — `now.format("%Y-%m-%d %H:%M:%S")`, name `time`.
  - `pub fn render_line(blocks: &[Block], first: bool) -> String` — `serde_json::to_string(blocks)`, prefixed with `,` unless first.
  - Win32 readers (not unit-tested): `read_cpu_times() -> Option<(u64,u64,u64)>` (`GetSystemTimes`), `read_mem_used_pct() -> Option<u32>` (`GlobalMemoryStatusEx.dwMemoryLoad`), `read_disk_free(root: &str) -> Option<u64>` (`GetDiskFreeSpaceExW`), `read_battery() -> Option<(u8, bool)>` (`GetSystemPowerStatus`; None if `BatteryFlag == 128` or `BatteryLifePercent == 255`).
- `main.rs`: print `{"version":1,"click_events":false}`, then `[`, then every second: gather [cpu, mem, disk `C:`, battery if Some, time], print `render_line`, flush stdout. Exit cleanly when a write fails (the pipe closed).

Keep the default console subsystem (do NOT add `windows_subsystem = "windows"`): stdout piping needs it, and i3win spawns it with `CREATE_NO_WINDOW`, so no console window appears.

### Task 6: Status process manager and click events

**Files:**
- Create: `crates/i3win/src/status.rs`; Modify: `main.rs`, `mainloop.rs` (`MainMsg::StatusUpdate(Vec<Block>)`, `MainMsg::StatusExited(Option<i32>)`), `app.rs`

**Interfaces:**

- Produces:
  - `pub struct StatusProcess { child: std::process::Child, stdin: Option<ChildStdin>, writer: ClickWriter, click_events: Arc<AtomicBool> }`
  - `pub fn StatusProcess::spawn(command: &str) -> std::io::Result<StatusProcess>` — spawns per Global Constraints; starts a reader thread that owns a `StatusParser`, reads stdout lines (`BufRead::lines`, lossy UTF-8), posts `StatusUpdate` for each `Some`, stores `parser.click_events` into the shared atomic after the header, and on EOF (or a read error) posts `StatusExited(None)` and ends.

  - `pub fn kill(&mut self)`.
  - `pub fn exit_block() -> Block` — `full_text: "status_command exited"`, `urgent: true`, `separator: true`.
- `App` gets `status: Option<StatusProcess>`. Spawn in `App::start` and after `Reload` (kill the old one first) when `config.bar.status_command` is Some. Spawn error → `blocks = vec![exit_block()]`. `StatusUpdate(b)` → `self.blocks = b`, flush. `StatusExited(_)` → `self.blocks = vec![exit_block()]`, `status = None`, flush (no automatic respawn). `StatusClick{..}` → `status.click(...)`. `shutdown()` → `status.kill()`.
