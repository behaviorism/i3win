# i3win Plan 4 — IPC and i3win-msg Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Speak the i3 IPC protocol over the named pipe `\\.\pipe\i3win-ipc` (requests, replies, event subscriptions), and ship `i3win-msg.exe`, an `i3-msg` clone.

**Architecture:** The wire format and every JSON reply/event builder are pure functions in `i3win-core::ipc`, computed from `&Wm`. The platform crate runs a pipe-accept thread and one reader thread plus one writer thread per connection. Requests travel to the main thread as `MainMsg::Ipc` with an `mpsc::Sender<String>` for the reply. Events come from `Effect::Ipc` during `flush()` and are broadcast to subscribers' writer channels.

**Tech Stack:** Rust 2021, `serde_json = "1"`, `windows = "0.58"` (`Win32_System_Pipes`, `Win32_Storage_FileSystem`).

**Spec:** `docs/superpowers/specs/2026-10-16-i3win-design.md`
**Depends on:** Plans 1–3 completed. Read `core/src/wm.rs` (`IpcEvent`, `Effect`), `crates/i3win/src/app.rs` and `mainloop.rs` first.

## Global Constraints

- Everything from Plans 1–3's Global Constraints applies.
- Wire format (exact): the 6 bytes `i3-ipc`, then the payload length as u32 little-endian, then the message type as u32 little-endian, then the payload (UTF-8 JSON). Replies use the request's type. Events use `0x8000_0000 | event_index`.
- Request types: RUN_COMMAND 0, GET_WORKSPACES 1, SUBSCRIBE 2, GET_OUTPUTS 3, GET_TREE 4, GET_MARKS 5, GET_BAR_CONFIG 6, GET_VERSION 7, GET_BINDING_MODES 8, GET_CONFIG 9, SEND_TICK 10. Unknown type → reply `{"success":false,"error":"unsupported message type"}` with the same type.
- Event indexes: workspace 0, output 1, mode 2, window 3, barconfig_update 4, binding 5, shutdown 6, tick 7.
- The pipe name defaults to `\\.\pipe\i3win-ipc`. Override with the `--ipc-pipe <name>` CLI flag (i3win) or `-s <name>` (i3win-msg). i3win sets env `I3SOCK=<pipe name>` for children it spawns via `exec`. i3win-msg reads `I3SOCK` when `-s` isn't given.
- The pipe is created with `PIPE_REJECT_REMOTE_CLIENTS`.
- Payloads larger than 16 MiB are rejected (connection closed) to avoid huge allocations.

## Review Focus

1. **A client that disconnects mid-message, or sends a bogus header**: only that connection closes; the server keeps accepting others. → test `decode_rejects_bad_magic_and_huge_len` in Task 1 + manual check in Task 3.
2. **A subscriber that stops reading**: broadcast never blocks the main thread. Writer channels are unbounded `mpsc` with a per-connection writer thread, and a send failure drops the subscriber. → code review in Task 3.
3. **Requests arriving while the main thread is busy**: the reply waits at most 5 s, then the client gets `{"success":false,"error":"timeout"}`. → code review in Task 3.
4. **Workspace names with Unicode, quotes or spaces** round-trip through RUN_COMMAND and GET_WORKSPACES unchanged. → test `unicode_workspace_names_roundtrip` in Task 2.
5. **The window-close event after the node is gone** still produces valid JSON (with `container.window` set). → test `close_event_without_node` in Task 2.

**Files:**
- Modify: `crates/core/src/ipc.rs`, `crates/core/src/wm.rs` (add `IpcEvent::Output` and emit `Output` from `set_outputs`; add `IpcEvent::Tick { payload: String }`)

**Interfaces:**
- Consumes: `Wm`, `Tree`, `arrange`, `Config`, `bar_height`.
- Produces:
  - `pub struct IpcContext<'a> { pub config_path: &'a str, pub config_text: &'a str }`
  - `pub enum Request { Reply(String), Subscribe(Vec<String>), Tick(String) }`
  - `pub fn handle(wm: &mut Wm, ctx: &IpcContext, msg_type: u32, payload: &str) -> Request` — for SUBSCRIBE parse a JSON string array (invalid → `Reply({"success":false,"error":"invalid subscribe payload"})`); for SEND_TICK → `Tick(payload)` (the server replies `{"success":true}` and broadcasts); everything else → `Reply(json)`.
  - `pub fn command_results_json(r: &[CommandResult]) -> String` — `[{"success":true}, {"success":false,"error":"…"}]`
  - `pub fn workspaces_json(wm: &Wm) -> serde_json::Value`, `outputs_json`, `tree_json`, `version_json(ctx)`, `bar_config_json(wm, payload)`, `binding_modes_json(wm)`
  - `pub fn event_json(wm: &Wm, e: &IpcEvent) -> (u32 /*event index*/, &'static str /*event name*/, String /*payload*/)`
  - `pub fn tick_event(first: bool, payload: &str) -> String` — `{"first":…,"payload":…}`

JSON shapes (field names exactly as in i3):
- **Rect**: `{"x":…,"y":…,"width":…,"height":…}`.
- **workspaces**: array in `sorted_workspaces` order of `{"id": node id, "num": num or -1, "name", "visible", "focused", "urgent", "rect": output rect, "output": output name}`.
- **outputs**: `{"name", "active": true, "primary": index == 0, "current_workspace": visible ws name, "rect"}`.
- **tree**: a recursive node. `{"id", "type": "root"|"output"|"workspace"|"con", "name": window title | ws name | output name | "root" | null for containers, "layout": layout.as_str() ("output" for Output nodes), "orientation": "horizontal"|"vertical" (Root/Output: "none"), "percent": percent or null for root/output/workspace/floating, "rect", "focused": node == wm.focused(), "focus": [ids of focus stack], "urgent", "fullscreen_mode": 0|1, "nodes": [tiling children], "floating_nodes": [floating windows]}`. Workspace nodes add `"num"`. Window nodes add `"window": hwnd as i64` and `"window_properties": {"class", "instance", "title"}`. Rects: window → its placement rect from `wm.arrange()` if visible, else `floating_rect` or `info.rect`; output/workspace → output rect; containers → `{0,0,0,0}`.
- **version**: `{"major":4,"minor":22,"patch":0,"human_readable":"4.22 (i3win 0.1.0)","loaded_config_file_name": ctx.config_path}`.
- **bar config**: empty payload → `["bar-0"]` if `config.bar` is Some, else `[]`. Payload `bar-0` → `{"id":"bar-0","mode":"dock","position":"top"|"bottom","status_command": … or null,"font": "pango:<family> <size>","workspace_buttons":…,"colors":{"background":"#rrggbb","statusline":…,"separator":…,"focused_workspace_border":…,"focused_workspace_bg":…,"focused_workspace_text":…, (same for active_/inactive_/urgent_ workspace and binding_mode_)}}`. Unknown id → `{"success":false,"error":"no such bar"}`.
- **binding modes**: `["default", …other mode names sorted]`.
- **config**: `{"config": ctx.config_text}`. **marks**: `[]`.
- **Events** (payload; event name):
  - `Workspace{change,current,old}` → `{"change", "current": ws node JSON (as in the tree, looked up by name; null if gone), "old": … or null}`; `workspace`
  - `Window{change,window}` → `{"change", "container": the window's node JSON}`; if the node is gone: `{"id":0,"type":"con","window":hwnd,"name":null,"nodes":[],"floating_nodes":[]}`; `window`
  - `Mode{name}` → `{"change": name, "pango_markup": false}`; `mode`
  - `Binding{command}` → `{"change":"run","binding":{"command": command,"event_state_mask":[],"input_code":0,"symbol":null,"input_type":"keyboard"}}`; `binding`
  - `Output` → `{"change":"unspecified"}`; `output`
  - `Tick{payload}` → `tick_event(false, payload)`; `tick`
  - (shutdown is built by the server: `{"change":"exit"}`.)

### Task 3: Named-pipe server and App integration

**Files:**
- Create: `crates/i3win/src/ipc_server.rs`; Modify: `main.rs` (the `--ipc-pipe` flag; start the server), `mainloop.rs` (add `MainMsg::Ipc { msg_type: u32, payload: String, reply: std::sync::mpsc::Sender<String> }`; subscriptions never reach the main thread), `app.rs`, `crates/i3win/tests/smoke.rs` (add the IPC test)

**Interfaces:**
- Consumes: `ipc::{encode, decode_header, handle, Request, event_json, tick_event, event_index, IpcContext}`.
- Produces:
  - `pub fn start(pipe_name: String)` — spawns the accept thread.
  - `pub fn broadcast(event_index: u32, event_name: &str, payload: &str)` — callable on the main thread; frames once with `EVENT_BIT | index` and `send`s to every subscriber whose set contains `event_name`; removes subscribers whose send fails.
  - `pub fn broadcast_shutdown()` — `broadcast(EV_SHUTDOWN, "shutdown", r#"{"change":"exit"}"#)`, then sleeps 100 ms.
  - Internal: `static SUBSCRIBERS: Mutex<Vec<(u64, HashSet<String>, mpsc::Sender<Vec<u8>>)>>`, `static NEXT_CONN: AtomicU64`.

Server behavior:
- Accept loop: `CreateNamedPipeW(name, PIPE_ACCESS_DUPLEX, PIPE_TYPE_BYTE | PIPE_READMODE_BYTE | PIPE_WAIT | PIPE_REJECT_REMOTE_CLIENTS, PIPE_UNLIMITED_INSTANCES, 65536, 65536, 0, None)`; `ConnectNamedPipe` (treat `ERROR_PIPE_CONNECTED` as success); wrap the handle as `std::fs::File` (`FromRawHandle`); `try_clone()` for the writer; spawn the connection threads; loop. If creation fails → log the error, sleep 1 s, retry.
- Writer thread: `for buf in rx { if file.write_all(&buf).is_err() { break } }`.
- Reader thread: loop { `read_exact` 14 bytes → `decode_header` (Err → break) → `read_exact` the payload → `String::from_utf8_lossy` }. For `SUBSCRIBE`: parse the event-name array locally with serde_json (invalid → reply failure); register `(conn, set, tx.clone())`; reply `{"success":true}`; if the set contains `tick`, also send the event `tick_event(true, "")`. Everything else: create `(rtx, rrx) = mpsc::channel()`, `mainloop::post(MainMsg::Ipc { msg_type, payload, reply: rtx })`, `rrx.recv_timeout(5 s)` → reply payload, or `{"success":false,"error":"timeout"}`; send `encode(msg_type, &reply)` through `tx`. On loop exit: remove the conn's subscriptions and drop `tx` (the writer ends).
- App: `on_main_msg(Ipc { msg_type, payload, reply })` → `ipc::handle(&mut self.wm, &ctx, msg_type, &payload)` where `ctx` = config path + config text (App keeps the last loaded text) → `Reply(s)` → `reply.send(s)`; `Tick(p)` → `reply.send(r#"{"success":true}"#)` then `broadcast(EV_TICK, "tick", &tick_event(false, &p))`; `Subscribe(_)` can't happen here (the server handles it), so reply with failure. Then `flush()` (RUN_COMMAND may change things).
- `flush()` step 1: `Effect::Ipc(e)` → `let (i, n, p) = ipc::event_json(&self.wm, &e); ipc_server::broadcast(i, n, &p)`.
- `Effect::Exec`: add `.env("I3SOCK", pipe_name)`.
- `shutdown()`: `broadcast_shutdown()` first.

### Task 4: `i3win-msg`

**Files:**
- Create: `crates/msg/Cargo.toml` (package `i3win-msg`, deps `i3win-core` path, `serde_json = "1"`), `crates/msg/src/main.rs`; Modify: root `Cargo.toml` members += `"crates/msg"`

**Interfaces:**
- Consumes: `ipc::{encode, decode_header, type_from_name, EVENT_BIT}`.
- Produces (pure, in `main.rs`, unit-tested):
  - `#[derive(Debug, PartialEq)] pub struct Args { pub msg_type: u32, pub socket: Option<String>, pub quiet: bool, pub monitor: bool, pub payload: String }`
  - `pub fn parse_args(args: &[String]) -> Result<Args, String>` — flags `-t TYPE`/`--type TYPE`, `-s PATH`/`--socket PATH`, `-q`/`--quiet`, `-m`/`--monitor`; the remaining args are joined with single spaces into the payload. Default type `command` (0). Unknown `-t` value → Err. `-m` without `-t subscribe` → Err("monitor requires -t subscribe").
  - `pub fn any_failed(reply: &str) -> bool` — true if the reply is a JSON array containing an object with `"success": false`.
- Behavior: socket = `-s`, else env `I3SOCK`, else `\\.\pipe\i3win-ipc`. Open it with `OpenOptions` read+write (on failure print `i3win-msg: cannot connect to <name>: <err>` to stderr and exit 1). Write the request, read one reply, print its payload unless `-q`. With `-m`: after the subscribe reply, keep reading messages and print each event payload on its own line until EOF. Exit code 2 if the type is `command` and `any_failed`, else 0.
